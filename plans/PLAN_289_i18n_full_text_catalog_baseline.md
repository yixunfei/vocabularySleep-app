# 计划 289: i18n 全量文本集中管理基线

## 基本信息
- **创建日期**: 2026-05-29
- **状态**: 已完成
- **负责人**: Codex

## 目标
在不修改任何代码文件的前提下，完成当前项目用户可见文本与页面文本的全量梳理，新增集中式 i18n 文案资源与覆盖清单，为后续逐页替换和统一翻译管理提供基线。

## 详细步骤
1. 回退当前分支到指定提交 `c38e2fee4f8b5df079d0398745fe82e9b6077ff9`，并清理全部工作区修改与未跟踪文件。
2. 扫描现有 `AppI18n`、ARB 资源、`pickUiText` 内联双语文本、`i18n.t(...)` 引用、页面文件和常见 Flutter 展示文本属性。
3. 生成集中式 i18n 文案目录，保留来源文件、行号、文本来源形态、建议 key、已有翻译与缺失语言状态。
4. 生成页面覆盖报告，按页面/模块列出文本数量、内联文本数量、已接入 key 数量与待迁移风险点。
5. 更新 changelog，记录本轮资源化基线与代码零改动边界。

## 风险评估
- **风险 1**: Dart 字符串中混有资源路径、技术 key、SQL、调试日志等非用户可见文本。
- **缓解措施**: 在集中目录中保留分类字段与来源上下文，不直接删除或改写代码；后续替换时逐页确认可见性。
- **风险 2**: 仅新增资源文件无法让运行时自动使用新目录。
- **缓解措施**: 本轮遵守“不修改代码”边界，将资源设计为可被后续 `AppI18n` 或生成式本地化接管的源数据。
- **风险 3**: 词典、测试、第三方依赖和文档中包含大量文本，但并非 UI 本地化对象。
- **缓解措施**: 本轮核心覆盖 `lib/` 应用源码与平台展示元数据；大型内容数据集在报告中单独标注为内容资源，不混入 UI 文案目录。
