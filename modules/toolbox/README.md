## Reverse Image Update (2026-05-26B)
- Reverse image result cards now hide long request/result URLs; action buttons remain for opening result page and source page.
- Aggregation lists now support per-engine incremental loading (`Load more`) instead of a fixed first-page cap, with stronger URL/title-based deduplication.
- Google flow now prioritizes resolving and parsing `https://www.google.com/search?vsrid=...` from Lens redirects/pages.
- Sogou flow now adds `window.__INITIAL_STATE__` + `/risapi/pc/risSearchlist` structured parsing fallback to improve source URL mapping.
- `remove.bg` is removed from reverse-image search-engine aggregation; it is treated as a future pre-processing capability candidate only.
- Feasibility note for future `remove.bg` pre-processing: evaluate API key management, per-call cost/quota, privacy/compliance for image upload, and region/network availability before rollout.

## Image Compression Update (2026-05-26)
- `image_compress` now routes to a functional local page in life tools instead of a placeholder info page.
- Supports local image picking, ratio-based or target-width resizing, JPEG quality control, and side-by-side preview.
- Shows source/output metrics (size, ratio, reduction, dimensions) and supports exporting compressed results.
- Export prefers save dialog and falls back to app-local documents directory when direct save path is unavailable.
- Current boundary: output format is JPEG (best for size reduction); transparency in source images will be flattened by JPEG encoding.

## Image Compression Update (2026-05-26C)
- Added multi-algorithm compression options in life tools image compression: `Auto best`, `JPEG balanced`, `JPEG aggressive`, `PNG lossless`, `GIF indexed`.
- Compression pipeline now decodes/resizes once, then encodes candidates and can auto-select the smallest output for maximum size reduction.
- Result metrics now include selected algorithm and encoding details.
- Export extension now follows actual result format (`.jpg` / `.png` / `.gif`) instead of fixed `.jpg`.
- Added smoke assertions for new algorithm controls visibility.

## Image Compression Update (2026-05-26D)
- Added optional lossy preprocess modes before encoding: `Original color`, `Grayscale`, `Black/white`.
- Added `BW threshold` control for black/white mode to tune aggressive binarization strength.
- Added DPI option controls: `No custom DPI` and `Write PNG DPI` with `72~300 dpi` slider.
- Compression pipeline is now `decode -> orientation -> resize -> preprocess -> encode`, so preprocess also affects `Auto best` selection.
- PNG encoding now supports writing DPI metadata through PNG physical pixel dimensions.
- Encoding detail now includes preprocess/DPI trace tokens (for example `gray`, `bw@0.50`, `dpi144(png-only)`).

## Life Tools Steganography (2026-05-26)
- `steganography` now opens a local media steganography page instead of a placeholder entry.
- Supports image/audio/video modes with shared encryption and restore workflow.
- Image steganography decodes the carrier and exports lossless PNG with RGB LSB payload, so the hidden text can be restored reliably.
- Audio/video steganography appends a structured tail payload to preserve original media bytes and best-effort playback compatibility.
- Encryption is now delegated to `ToolboxCryptoService`, a reusable local crypto library for toolbox modules.
- Supported enabled encryption options: `AES-GCM`, `Twofish-GCM`, `Camellia-GCM`, fixed cascades, user-defined cascades, `SHA256 stream`, `RC4 legacy`, and `No encryption`.
- Serpent/Kuznyechik placeholders were removed and replaced with implemented `SHA-256/RSA`, `ECDSA`, and `Whirlpool` layers: RSA/ECDSA are verification/signature modes, and Whirlpool is available for hashing/MAC.
- Strength options: `standard`, `strong`, and `extreme`; encrypted modes derive keys with scrypt, use at least 256-bit per-stage key material, and can combine passphrase plus optional key-file material.
- The file workspace now encrypts file bytes and embeds the encrypted payload into an image/audio/video carrier, then restores the original bytes from generated stego media.
- Key files can be picked manually or generated locally at a chosen byte length and exported.
- The same page also exposes hash calculation (`SHA-256`, `SHA-512`, `SHA3`, `BLAKE2b`, `Whirlpool`).
- VeraCrypt boundary: the module borrows the cascade, independent-stage-key, KDF/hash, and keyfile strategy, but it does not create VeraCrypt-compatible volumes, headers, or XTS devices.
- Risk boundary: image outputs must not be re-saved as lossy JPEG; audio/video tail payloads may be rejected by strict media parsers.
- Risk boundary: losing the key file makes any payload encrypted with it unrecoverable, even if the passphrase is known.
